# PJS — Codified PACT as a General Research Harness

**Date:** 2026-10-03

PACT should be able to evolve from field intuition into a reusable research harness.

## Transfer from PJS / Quant thinking

The useful part of quant-style reasoning is not limited to markets. The same discipline can be applied to ordinary companies:

- define the object clearly;
- identify measurable dimensions;
- separate facts from hypotheses;
- collect evidence;
- model relationships;
- expose missing information;
- iterate after feedback.

PACT provides the business ontology. PBCT provides the engineering capability.

## Codified loop

**Field observation / company name**
→ standardized PACT schema
→ evidence collection
→ business / financial reasoning
→ relationship graph
→ banking / strategic opportunity map
→ report
→ informal talk
→ corrected assumptions
→ stronger next report

This can be implemented as a Codex / agent workflow once one excellent reference example is available.

## Why it matters for PJS

This creates a general-purpose research habit:
- a new company can be understood faster;
- interviews gain better examples;
- informal conversations become more specific;
- business reasoning becomes testable and reusable;
- technical ability is tied to real economic objects.

## Priority rule

Do not hide inside automation.

Current priority remains **high-quality informal talk, interviews, field DD and real interactions**. The code should remove repetitive work and prepare stronger questions.

The desired state is not “more generated reports.”

It is:
**better real-world understanding per unit AlphaTime.**
